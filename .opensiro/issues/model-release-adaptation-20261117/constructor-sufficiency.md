## 3. Minimal complete S4 first-party C construction

**Required property:** A first-party, developer-composable **S4-specific** decision and return path for autonomous future model-lifecycle choice within one Paperclip company. No fixed count of ports, no separate general VSM controller and no mandatory five-port or ten-test recipe.

| Necessary native component / port | Existing API/source | Smallest proposed integration | Legitimate owner, effect and return |
| --- | --- | --- | --- |
| Future model-release case and authoritative options | [Adapter discovery](https://github.com/paperclipai/paperclip/blob/f4a3f85b89b2dae7889b0a9c7fee07ed47b554cb/server/src/adapters/registry.ts); [manual audit](https://github.com/paperclipai/paperclip/blob/f4a3f85b89b2dae7889b0a9c7fee07ed47b554cb/doc/adapter-model-audit-2026-11-18.md) | Company-scoped source URL, observed/effective date, model and snapshot version, known/unknown compatibility, deduped hold/retain/stage options | S4 actor owns future scenario choice; source ingestion does not grant provider access |
| Authorized decision and later-use effect | [Agent config revision and guards](https://github.com/paperclipai/paperclip/blob/f4a3f85b89b2dae7889b0a9c7fee07ed47b554cb/server/src/services/agent-configuration.ts), [public MCP update action](https://github.com/paperclipai/paperclip/blob/f4a3f85b89b2dae7889b0a9c7fee07ed47b554cb/server/src/services/public-mcp/expanded-capabilities.ts) | Bind composed agent decision, compare version, enforce config consent/board policy and pending approval, guard active sessions, restrict to future runs | S4 selects; Paperclip enforces; no silent reviewer or S5/credential changes |
| Effective-state return and revision | [Heartbeat service](https://github.com/paperclipai/paperclip/blob/f4a3f85b89b2dae7889b0a9c7fee07ed47b554cb/server/src/services/heartbeat.ts), [config revision API](https://github.com/paperclipai/paperclip/blob/f4a3f85b89b2dae7889b0a9c7fee07ed47b554cb/server/src/routes/agents.ts) | Correlate S4 choice→config revision→subsequent real run resolved model/result, failed or rejected choice→hold/revisit | Next company decision receives observed effect; zero configuration mutations for no-go choices |

**Architectural C-sufficiency argument:** Option one — ask a scheduled CEO agent to read releases then use generic configuration tools; this may be a useful native manual/agent workflow but does not guarantee first-party source-specific state and feedback, and model write consent may be insufficient. Option two — optional plugin consuming available adapter refresh and run events, with a company-scoped decision record, an installed configured S4 actor and existing guarded configuration API. This is preferred if current plugin SDK actually supplies lawful hooks and version checks. Option three — a minimal server-owned S4 decision/return service only for missing guarded writes and next-run correlation, reusing all other shipped modules; use only if plugin cannot close the chain. In every option inspect effective source and authorization rather than assuming a generic callback is C. The source-native requirement is **Paperclip's existing agent_config:update, model catalog, config revisions, heartbeat lifecycle and independent reviewer guard**, not portable generic "agent observes external event" prose.
**Explicit non-goals:** No S5 purpose changes, new policy owner, blanket A regrade, mandatory provider polling at every heartbeat, credential purchase, unreviewed model swap during running work, reactive 429 fallback implementation, imposed universal port count or public product feature.
**Implementation dependency graph:** Verify first-party source and pending #10125 permission → P1 compatibility/role/version fences and source signal → install configured company S4 actor / P0 choice record → stage safe authorized future config change → capture true next-run feedback → native acceptance; Index regrade remains a separate future process.

## 4. Priorities, optional alternative and stopping rules

**P0 and P1:** P0 exactly the S4 source-native model-lifecycle decision/apply/feedback loop, P1 dated release provenance and per-agent compatibility/rights/idle-version and native test proof. Both derive from [roadmap.md](roadmap.md) rather than creating competing scope.
**P2:** NONE. No secondary S3, S3*, or S5 constructor mandated.
**Alternative path:** Implement only the original #20848 advisory or leave operator to manual refresh and approval, if that yields preferred benefits at lower cost. Such parent/manual control is a valid product choice even without an autonomous S4 constructor.
**Stop:** Already shipped native complete source-first S4 ownership, incoherent discretionary actor, unguarded model mutation, board prohibition, unsupported runtime, overlap with merged feature, or source fact impossible to resolve. Separate architectural proposal GO from adoption approval.
