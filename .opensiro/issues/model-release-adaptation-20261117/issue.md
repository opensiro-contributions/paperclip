## 2. Selected construction hypothesis and operator outcome

**Target transition:** S4=— -> S4=C
**Function-specific disturbance:** A provider announces a model end-of-life or materially new model, while actual per-agent CLI versions, accounts and current tasks differ; the next safe company configuration needs a justified prospective decision.
**Proposed C capability (P0):** Developer-composed company S4 actor obtains a source-dated change and a versioned company/agent compatibility snapshot; decides retain, hold, or propose a compatible successor; Paperclip validates bounded decision authority and applies permitted future-run configuration at a safe boundary; the next real heartbeat returns resolved model or a failure/denial to the company decision record. Actor choice, not a hardcoded alert, changes later operation.
**Best native operator alternative:** Monitor [Paperclip's manual adapter-model audit](https://github.com/paperclipai/paperclip/blob/f4a3f85b89b2dae7889b0a9c7fee07ed47b554cb/doc/adapter-model-audit-2026-11-18.md), fetch [native adapter catalogs](https://github.com/paperclipai/paperclip/blob/f4a3f85b89b2dae7889b0a9c7fee07ed47b554cb/server/src/adapters/registry.ts), check execution environment and manually update model under existing permissions. A lightweight notification (#20848) could be sufficient for operators who do not want autonomous decisions.
**Expected user benefit:** HYPOTHETICAL earlier detection and safer company-wide preparation for model changes; no measured demand, time saving, cost or deployment.
**Architectural sufficiency argument:** Reuse source-native model discovery, the company-scoped configuration authorization boundary, config history, runner compatibility checks and heartbeat result traces. The missing S4-specific element is a versioned future-signal-to-options decision record with an actual developer-bound autonomous option owner and guarded return to eligible later execution. Do not build a second model router or replace reserved board policy.

## 5. Proposed acceptance and stop gates

**Future positive test:** An installed company S4 actor sees two dated release scenarios, lawfully chooses retain versus candidate, an authorized choice applies to the next idle eligible agent run, and the effective model and outcome are returned to the case while active runs remain unchanged.
**Future negative test:** Unsupported or unverified CLI/account, stale config revision, revoked or absent authority, protected reviewer or board denial blocks writes and reports a specific reason without false successful feedback.
**Proposed falsifier:** Source/CI shows native autonomous prospective loop already exists, or proposed first-party bridge cannot preserve company/board and active-run boundaries.
**Validation state:** NOT_RUN — this roadmap includes read-only source and schema inspection, not executed product tests.
